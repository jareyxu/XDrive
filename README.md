# XDrive

**XDrive 是一款可自行托管的个人云盘。文件在浏览器内加密后再上传，服务端保存密文。**

> **当前稳定版：v2.0.9。** 优化自动传输并发和上传流水线，设置页显示实际并发上限与内存预算限制，调整文件夹加载提示。SQLite schema 保持 9，加密文件格式不变。

## 功能

- 单用户、自托管的 Web 云盘，可部署在自己的 Linux VPS。
- 浏览器端加密文件及目录索引；服务器不保存文件名、文件夹名或文件内容的明文副本。
- 文件和文件夹管理、上传续传、回收站、图片与视频预览，以及 PDF、文本、Markdown 和代码预览。HEIC/HEIF 图片保留原文件加密存储；本机浏览器无法原生显示时，使用按需加载的本地解码器生成预览和缩略图，解码输入上限为 32 MiB。
- 视频在支持的浏览器中按需读取并解密分块；手机端限制解密缓存和读取并发。流式会话不可用时，仅对不超过配置上限的小视频尝试整体内存播放，默认上限 256 MiB。视频编码须受浏览器支持。
- 流式单文件下载和 ZIP64 文件夹导出。
- 本地 SQLite 与文件系统存储；部署可使用现有 Nginx 或 Caddy。无需 Docker。

## 隐私与安全

XDrive 在浏览器中使用 Argon2id 派生密钥，并使用 AES-256-GCM 加密文件数据。密码和未解包的 Vault Key 不会发送给服务器。登录所需的认证材料会通过 HTTPS 发送，服务器也能看到密文对象大小和数量、访问时间、客户端 IP 等运行信息。

客户端加密不能抵御被攻陷的浏览器、恶意扩展，或能替换 XDrive 网页代码的服务器。密码遗忘后，XDrive 无法恢复加密密钥；服务器备份也不能代替密码。使用前请先在测试环境验证，并实际演练备份与恢复。

## 安装与部署

从 [GitHub Releases](https://github.com/jareyxu/XDrive/releases/latest) 下载以 `-package.tar.gz` 结尾的完整稳定版安装包与 `SHA256SUMS`。选择与你的 VPS 架构相符的 `amd64` 或 `arm64` 包；校验归档后解压其中的 `install.sh`，再按提示安装。

安装时提供域名、管理员用户名、数据目录和反向代理。若使用已有 Nginx 网站，可选择 `--proxy nginx`，安装器会为 XDrive 增加独立虚拟主机；也可以选择 Caddy。建议使用独立子域名（例如 `drive.example.com`），目前不支持挂载在 `example.com/drive` 这样的 URL 子路径下。已安装旧候选版的用户应先备份并校验备份，再使用对应版本包内的升级脚本。

Linux 安装脚本目前面向 Ubuntu 24.04 或 Debian 12（amd64／arm64），可配置 Nginx 或 Caddy。Nginx 模式会为 XDrive 添加独立的虚拟主机，不会改写原有网站配置。使用子域名（例如 `drive.example.com`）；当前不支持把应用挂在 `example.com/drive` 这样的 URL 子路径下。升级前请创建并验证外部备份；不要在没有可用备份时执行升级。

v1.3.4 和 v1.3.6 可通过网页更新到 v1.3.7。已经安装的 v1.3.5 保留着不同的七成员校验器，需要用 v1.3.7 完整包中的 `upgrade.sh` 手动升级一次。之后，新更新器自动选择完整包，支持新增和移除发布资源。

v1.3.7 更新器按发布清单安装数量可变的文件，失败时恢复完整应用目录和数据库。新安装和手动升级请选择以 `-package.tar.gz` 结尾的完整包；原文件名用于旧版更新器过渡。协议及跨版本过渡说明见[发布包与升级兼容指南](docs/release-packages.md)。

设置页现已支持检查并安装 GitHub 上的最新稳定版。新安装会自动配置独立的 root systemd 更新任务；从 v1.3.1 手动升级到 v1.3.2 后，需要以 root 运行一次 `xdrive enable-web-updates`。更新按钮会显示官方 GitHub 发布页并要求再次确认；服务器只安装该仓库的最新稳定版，并核对该发布页提供的 SHA-256 清单。归档与清单来自同一 GitHub 发布源，此检查不等于独立离线签名；使用此功能需要 VPS 能通过 HTTPS 访问 GitHub，并信任 XDrive 的 GitHub 发布账号。

## 本地开发

开发环境需要 Go 1.27.1、Node.js 26.0.0 和 pnpm 11.24.0：

```sh
make web-install
make build
./dist/xdrive init
./dist/xdrive serve
```

`init` 会生成一次性设置链接。默认服务只监听本机回环地址。开发、构建和测试命令见 [Makefile](Makefile)。 维护者发布流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 重要限制

- V1 面向单个用户，不提供注册、多用户、分享链接或密码找回。
- 备份不会自动运行；已登录用户可在设置页生成并下载完整备份。请把备份保存到 VPS 以外，并定期验证恢复流程。备份包整体不额外使用密码加密，应按敏感文件保护。
- 浏览器和移动设备的后台挂起、下载与媒体播放行为各不相同；未列出的设备和浏览器组合不作兼容承诺。播放失败时可复制诊断，内容只包含失败阶段、浏览器信息、文件大小和错误类型，不包含文件名、密钥或播放会话地址。
- 加密格式升级后不能静默降级到旧版；升级前请创建并验证备份，遇到回退提示时先阅读数据影响说明。

网页备份的下载、校验和迁移说明见 [备份恢复指南](docs/web-backup.md)。

## 传输性能配置（v2.0.6）

v2.0.6 提供以下优化：单文件和 ZIP 下载按顺序输出、提前读取后续分块；批量上传最多同时处理两个文件，目录创建与最终提交串行进行。加密分块仍为 8 MiB，无需数据库迁移。

设置 → 传输提供自动优化、上传和下载最大并发（1–8）、下载流水线预算（64/128/256 MiB）。自动模式从最多 4 路开始，同时受用户设置、服务器上限和下载内存预算约束；默认最大并发为 4，64 MiB 下载预算实际允许 2 路下载，4 路需 128 MiB，8 路需 256 MiB。设置页显示可用上限，并提供显式调整预算的按钮。自动模式仅在实际并发达到目标的观察窗口中评估收益，收益不足或服务器繁忙时回退，空闲 30 秒后的新任务重新起步。上传会在有界缓冲内提前准备下一块，并在加密完成后释放明文。原有用户设置会保留。手机可保持默认；高速桌面设备可在测量后提高上限和预算，下载预取窗口从下一次下载生效。

流水线预算限制的是应用预取槽位，按每个 8 MiB 分块预留 32 MiB 处理空间；不等于浏览器进程总内存上限，也不包含内存下载回退中保存的完整文件。所有前台下载共享预取预算。实时速度按加密网络字节统计，含重试流量，与已校验完成的文件进度分开。

服务器 TOML 配置可增加以下项目，修改后重启服务：

```toml
upload_concurrency = 4
download_concurrency = 8
```

也可使用 `XDRIVE_UPLOAD_CONCURRENCY` 和 `XDRIVE_DOWNLOAD_CONCURRENCY` 环境变量覆盖，允许范围均为 1–64，分别限制服务进程同时接收的对象 PUT 和提供的对象 GET/HEAD。超限返回带 `Retry-After` 的 `503 transfer_busy`，客户端退避重试，持续繁忙则停止并提示重试。客户端会读取服务器能力，自己的并发不超过服务器上限。较高上限适用于更强的服务器或多个设备同时访问，不保证单次传输一定更快。

低配 VPS 可保留默认值；高配 VPS 可逐步提高至 8/16 等值，比较实际吞吐量、CPU、磁盘延迟和内存后再决定。不要为提速关闭持久化同步、对象完整性校验或配额检查。
